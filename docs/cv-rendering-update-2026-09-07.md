# CV 与 3D 渲染增量改进 · 2026-09-07

## 本轮交付

保留 Three.js + Python 的现有结构，新增可选 Face Landmarker + OpenCV PnP 头部位置求解；保留轻量 BlazeFace 作为默认。网页沿用既有 Sites/Vinext 构建流程，只在本机运行，没有注册站点或云端发布。

本轮所说的人脸识别是观看位置/朝向追踪，不是身份识别、活体检测或视线估计。

## 为什么增加第二种 CV 模式

| 路径 | 当前实现 | 适用与边界 |
|---|---|---|
| 轻量 `detector` | 双眼距离估深、去畸变、位置关联和 One Euro 滤波 | 保留已有行为；转头缩短图像眼间距，会被误判为后退 |
| 增强 `landmarker` | 单人视频模式，选 16 个参考点，PnP RANSAC + LM 细化，质量门限 | 针对转头的几何误差；通用脸型、遮挡和镜头内参仍限制真人精度 |

增强模式没有启用表情系数，也没有把 MediaPipe 的面部变换矩阵直接当成真实米制位置。只追踪一人，使视频模式可使用其内置平滑；这不是可靠的多人身份锁定。[MediaPipe 配置说明](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python)

PnP 通过已知三维参考点、二维观测和相机参数求解姿态。本项目用通用脸型的眼中心间距缩放至假设瞳距，原点置于双眼中点，先用 RANSAC 排除异常对应点，再做 LM 细化；重投影残差仅说明模型与图像的拟合程度，不等于真实三维定位误差。[OpenCV PnP 文档](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)

当前质量门限要求至少 12/16 个内点，重投影阈值随图像宽度缩放；过大侧转、俯仰、翻转、异常深度被拒绝。新校准还要求接近正面。转头不应直接驱动虚拟相机旋转：虚拟窗口的屏幕平面必须保持固定，只使用观看点移动改变离轴投影。

### 相机与屏幕标定

新增 `FACE_CALIBRATION_PATH` 读取 OpenCV 针孔内参和畸变。要求文件包含 `width, height, fx, fy, cx, cy, distortion`；同宽高比纯缩放可换算内参，宽高比改变会报错。即使宽高比相同，换镜头、数字变焦、裁剪或摄像头模式改变也要重新验证；代码不能自动识别所有裁剪。

`config/camera.example.json` 是格式示例，不是测量结果。保留 `example_only` 时程序拒绝使用；必须替换为实际标定值，不能仅删除标记来假装完成标定。

`intrinsics_calibrated=true` 只表示载入内参，`calibrated` 仍为 false。当前前端支持摄像头与屏幕平行时的 X/Y/Z 平移偏置，尚未处理旋转外参；个人脸型及瞳距也尚未联合标定。前端已有可见窗口物理宽度和中性距离输入，但不等同于完整外参模型。本轮没有凭经验编造这些物理数值。

## 采集、稳定和可观测性

- 摄像头线程持续读帧，推理线程只取单槽最新帧，慢时跳过旧帧而非堆队列。
- 读取后或推理后超过 250 ms 的结果不发布；断流清空缓存，重连代次阻止上一次连接的结果混入；缓存超过 500 ms 不再作为最新观测返回。
- 文件回放按声明 FPS 节流，避免解码线程瞬间耗尽文件；它仍是实时回放，不是逐帧评测工具。
- 前端中性校准需要至少 10 个稳定样本，时间窗扩为 1.2 秒，已覆盖 8 Hz 合成输入；质量不合格的样本不参与校准。
- 增加推理时间、取帧速率、队列年龄、覆盖帧数、有效 CV 速率和重投影残差，区分相机慢、推理慢、未检出与姿态异常。
- 轻量与增强模式手动选择，不逐帧互相回退，避免两套深度尺度突然切换。

“只用最新帧”不能保证相机驱动没有缓冲；读取完成时间不是曝光时间。当前没有通过长时外推来伪造高频观测。

## 3D 与高斯渲染

沿用上一轮的结论：当前技术栈最适合 **Three.js 负责窗口投影与网格，Spark 负责可选高斯展示**。相邻 gsplat / graphdeco 更适合离线训练，SuperSplat 适合清理和准备资产；Unity 路线需要另做原生应用，不能直接替换网页渲染器。完整目录对比见 [上一轮记录](rendering-tracking-review-2026-09-06.md)。

新增的渲染控制：

- 像素预算：默认 8.3 MP，同时受设备像素比和用户上限约束；改变渲染分辨率，不改 CSS 窗口或投影尺寸。
- 动态分辨率：默认关闭。开启后两次连续慢窗口才下降，六次快窗口才逐步恢复，缩放范围 0.5–1，避免频繁来回变化。它观察帧间隔，不是 GPU 专用计时器；CPU 受限时降像素可能无效。
- 高斯屏幕空间滤波和覆盖范围：通过 Spark 的 `blurAmount`、`maxStdDev` 接入。提高滤波可能减少细小高斯闪烁但使画面柔化；缩小覆盖范围减少透明叠加，同时可能损失边缘。这不是完整的 Mip-Splatting 训练/滤波方案。[Spark 参数文档](https://sparkjs.dev/docs/spark-renderer/)
- 保留按需加载 Spark、固定屏幕平面的离轴投影、静态阴影缓存以及本地模型入口。当前没有启用大场景分块 LOD。

4,096 个高斯的程序化测试环仅验证渲染通路，不代表扫描精度。没有真实扫描模型、同视角参照图和 GPU 帧时间之前，不宣称画质提升百分比或大模型稳定帧率。

### 合成几何实验

使用同一个通用脸型生成无噪声投影，再反求位置；相机参数完全正确，真实深度为 0.65 m：

| 转头角度 | 眼间距法估计深度 | 新 PnP 估计深度 |
|---|---:|---:|
| 0° | 0.6512 m | 0.6500 m |
| ±30° | 0.7507 m | 0.6500 m |
| ±45° | 0.9176 m | 0.6500 m |

复现：主目录运行 `.venv\Scripts\python.exe scripts/benchmark_head_pose.py`。这验证算法处理转头的几何逻辑，**不是独立真人精度验证**；同模型生成和反解会高估现实效果。

### 本机摄像头短时采样

增强模式，1280 × 720，每组 90 个结果，无图像或位置历史落盘：

| 采样组 | 结果速率 | 推理均值 | 有效追踪比例 |
|---|---:|---:|---:|
| 初次接通 | 16.05 Hz | 10.73 ms | 100% |
| 中途复测 | 15.86 Hz | 9.17 ms | 81.1% |
| 加入拒绝原因后 | 15.68 Hz | 9.03 ms | 72.2% |

最后一组 65 次接受、25 次未检出人脸，没有姿态或运动跳变拒绝。取帧均值 15.76 Hz，队列年龄均值 1.07 ms，采样期间覆盖帧数为 0，读取完成到本机接收均值 16.49 ms。有效帧重投影残差均值 2.92 px、P95 3.45 px。

没有控制观看者持续在画面内，也没有位姿真值、统一光照或严格 A/B 条件，因此这些比例不能当检测准确率，也不能证明增强模式比轻量更稳。当前只可推断该短样本中没有推理积压，结果速率接近实际取帧速率。读取到接收延迟不含曝光、驱动缓冲、网页平滑及显示延迟。

另外单独重启轻量模式验证兼容性：90 包、15.47 Hz，推理均值 6.73 ms，无队列覆盖，追踪有效比例 28.9%。该模式当前未报告细分拒绝原因，且采样不同时、动作未控制，不能据此比较两种模式检测率。收尾恢复增强模式供试用。

服务状态确认增强模式运行，网页 HTTP 返回 200。本轮没有执行浏览器画面/交互自动验收，不把构建成功当作视觉效果已通过人工验收。

## 本机试用

先关闭占用同一摄像头/端口的旧服务，再在主目录启动：

```powershell
.\.venv\Scripts\face-tracker.exe serve --tracker landmarker
```

另一终端进入 `web`，运行 `npm run dev -- --host 127.0.0.1 --port 3000`，打开 [本机页面](http://localhost:3000/)。正面稳定约一秒校准，然后分别测试平移、前后移动、原地小幅转头；不要把头部转动和大幅平移混在首轮对比中。返回轻量模式时停止后端，改用 `--tracker detector`，网页会重连并重新校准。

在 `web` 目录运行 `node tests/live-tracking.mjs` 可获得 90 包聚合诊断。该工具只读取本机位置服务，不保存图像，统计值不是精度真值。

## 隐私与依赖边界

程序处理摄像头画面在本机内存中进行，不建立身份数据库，不保存人脸照片。首次运行可能从官方地址下载模型。

本轮日志发现 MediaPipe 0.10.35 的 Clearcut 统计发送尝试。维护者说明预编译包包含遥测，没有官方关闭 API，并表示不发送输入数据。当前未确认统计发送成功，也没有证据表明图像上传；同时不能承诺该依赖完全无外联。严格离线版本需要另行验证源码构建或网络隔离。本轮没有修改全局防火墙、hosts 或 TLS 检查。[维护者回复](https://github.com/google-ai-edge/mediapipe/issues/6291#issuecomment-4896121772)

通用脸型参考点来自 Google MediaPipe 的 Apache-2.0 资源，代码中保留来源说明；并非从本次使用者采集的模板。[原始模型](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/modules/face_geometry/data/canonical_face_model.obj)、[项目许可](https://github.com/google-ai-edge/mediapipe/blob/master/LICENSE)

许可副本保存在 [docs/licenses/mediapipe-Apache-2.0.txt](licenses/mediapipe-Apache-2.0.txt)。本项目对选取的坐标进行了居中、轴向变换和瞳距尺度换算。

## 下一步优先级

1. 对实际摄像头标定内参，实测窗口尺寸、眼睛到屏幕距离及摄像头安装倾角；建立相机到屏幕的外参变换。
2. 用相同的带参照动作测试两种模式：静止抖动、固定位置转头漂移、前后移动比例、短遮挡恢复。先取得可比较证据，再决定默认模式。
3. 使用清理后的真实高斯资产做同视角对比，定位排序、欠采样、透明叠加或显存问题，再评估 LOD 和训练侧抗混叠。

尚未完成：真人毫米级精度验证、严格离线部署、相机到屏幕外参、浏览器视觉验收和大场景高斯性能验收。
